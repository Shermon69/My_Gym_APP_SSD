--- 5. Impact ---
Anyone who can read the repository can obtain the JWT signing key and forge a
token for a known user's ID. The authentication middleware accepts tokens
signed with this key, allowing impersonation of that user on protected routes.
Admin authorization separately loads the user's roles from the database, so
this finding alone does not let an attacker add an admin role to a forged JWT;
impersonating an administrator requires knowing an administrator user's ID.

Result: Critical hardcoded JWT signing secret; enables user impersonation and
authentication bypass for accounts whose IDs are known. A separate hardcoded
Express session secret is also present.
